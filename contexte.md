# Contexte du dépôt

Mémoire du dépôt pour les agents, à consulter avant toute recherche. Ne le lis pas en entier (plus de 70 Ko) : lis ce début et « En bref », puis cherche avec Grep les mots de ta tâche (fichier, vue, fonction, préfixe CSS) et lis seulement ces lignes ; chaque ligne traite un sujet. Studio l'impose à chaque agent Claude Code (consignes « Mémoire du dépôt », Réglages → Consignes et contexte).

**L'entretenir** — à la fin d'un travail, ajoute ici ce que tu as appris de durable et qui t'aurait fait gagner du temps : une ou deux lignes, dans la bonne section, commençant par les mots qu'on y cherchera (en gras, puis fichiers et fonctions) : c'est par Grep qu'on la retrouve. Corrige ou retire ce qui est devenu faux. Pas de journal, pas d'état d'avancement, rien que le code dise déjà en clair. Désigne le code par fichier et nom de fonction, jamais par numéro de ligne. Si le code contredit ce fichier, c'est le code qui a raison : corrige le fichier.

## En bref

- Studio : notes, tâches, projets, agents Claude Code. Une app web en TypeScript strict (`src/` → `dist/` par esbuild, sans framework), embarquée telle quelle dans une coquille Swift pour Mac et iPhone (`native/`).
- La carte complète des fichiers est dans `README.md`, section « Architecture » : ne la recopie pas ici, lis-la au besoin.
- Tout est rédigé en français : interface (tutoiement), commentaires, README, messages des scripts. Les commits sont en anglais, au format Conventional Commits.
- **Langue de l'interface (anglais par défaut)** : le code reste en français ; `src/ui/i18n.ts` traduit le DOM à la volée (MutationObserver) depuis `src/ui/i18n/dict-{a,b,c}.ts` (clé = texte d'un nœud entre deux balises ou valeur de title/placeholder/aria-label/alt/data-tip, variables en `{0}`), remplace `fr-FR` des dates/nombres par `en-GB`, ne touche ni `.md`, `code`, `pre`, champs, `[contenteditable]`, `[data-no-i18n]`, ni un texte égal à un titre de note (`i18n.guard`). Tout nouveau libellé = une entrée de dictionnaire. Comparer un texte déjà posé avec `i18n.t(texte)`, jamais avec le français brut (sinon réécriture à chaque appel). Hors DOM (notifications) : `i18n.t`. Réglage `localStorage studio.lang` (Réglages → Apparence, recharge la page) ; la page l'envoie au Mac par le message `lang` (UserDefaults `studio.lang`, menus de `native/macOS/main.swift`).
- Demande du 23 nov. 2026 : « au plus simple », « trop de données affichées ». Par défaut une vue montre l'essentiel sur une ligne ; le reste se replie (menu « … », `<details>`, « Plus »), et un bloc vide ne s'affiche pas.

## Build et versions

- L'app Mac embarque ses fichiers web : un changement dans `src/` n'y apparaît qu'après reconstruction (`studio update`) ou installation d'une Release.
- `native/build-mac.sh` inscrit `StudioCommit` et `StudioBuilt` dans l'`Info.plist` ; l'updater et `studio version` s'en servent.
- La CI (`.github/workflows/build.yml`) publie une Release à chaque push sur `main`, avec `Studio-macOS.zip`. Un seul job macOS (`native` : app Mac puis compilation iPhone), sauté sur une PR qui ne touche pas au natif (étape « Ce que la PR touche » : toute nouvelle source dont dépend le natif doit entrer dans son expression). `native/build-mac.sh` compile les architectures de `STUDIO_ARCHS` en parallèle (les deux par défaut). Les pull requests sont fusionnées sur GitHub : le dossier local ne les reçoit pas tout seul.
- **Signature de l'app Mac** : ad hoc par défaut ; `SIGN_IDENTITY` (posé par la CI sur un push, si les secrets `MACOS_CERTIFICATE`… existent) fait signer `build-mac.sh` en Developer ID avec hardened runtime et `native/macOS/Studio.entitlements`, puis le job `macos` notarise et agrafe. Sous hardened runtime, toute nouvelle ressource protégée (caméra, Apple Events…) demande son droit dans ce fichier, sinon elle échoue en silence dans l'app publiée seulement.
- **Concurrence CI** (`build.yml`) : main a un seul groupe (un build à la fois, le plus récent remplace celui en attente, jamais d'annulation en cours) ; deux builds main en parallèle publiaient dans le désordre (v1.0.301 après v1.0.302, npm en échec). Le job release saute si la dernière Release contient déjà le commit (« Déjà publié ? »). Une PR `closed` lance une exécution vide qui annule son build en cours. Un job macOS « cancelled » au bout de 15 min sans étape = runner jamais attribué (capacité GitHub), pas un bug du workflow.
- **Installeur** : `site/install.sh`, servi par Pages (`curl … | sh`), prend le zip de la dernière Release sans quarantaine. Tant que l'app n'est pas notarisée, c'est la voie d'installation mise en avant (README, site) ; un zip téléchargé au navigateur est bloqué par Gatekeeper.
- `studio update` avance donc d'abord `main` jusqu'à GitHub (avance simple), puis construit ; `studio update --local` construit tel quel ; `studio version` compare app installée, dossier et GitHub.

## Pièges

- **Outils dans la bulle d'un agent** : `node` est dans `/usr/local/bin`, absent du PATH (`PATH=/usr/local/bin:$PATH npm run verify`) ; `node_modules` est un lien vers le stock partagé (voir « node_modules des copies »). `scripts/shot.ts --pont scripts/shot-pont.js` simule l'app Mac ; pour simuler des limites d'abonnement, copier le pont dans /tmp et y changer la réponse de `claude limits`.
- **CSS** : un fichier par domaine importé en tête de `css/app.css`, `motion.css` toujours en dernier (il redessine `.sel` et les entrées). Pas de classe `run` : elle heurte le toast `.run`.
- **Anciens noms gardés exprès** : identifiant de bundle `app.carnet.notes`, schéma `carnet://`, pont `window.carnet`, base IndexedDB `carnet`. Les renommer ferait perdre les données des apps installées.
- **Un agent lancé par Studio est confiné** : `--restricted`, et sur le Mac une bulle Seatbelt (`native/Shared/AgentSandbox.swift`, `sandbox-exec -p`, réglage `terminal` coché à l'origine) : écriture limitée à sa copie, au `.git` du dépôt et aux caches ; lecture fermée sous `/Users` et `/Volumes` sauf le projet et une liste blanche d'outils (`tools`/`toolFiles`/`caches` dans `build` : config git/gh/npm, gestionnaires de node, dossier de `claude`, dossiers du PATH réglé ; jamais `.zshrc` ni les clés SSH) ; données de Studio, autres projets et autres sessions illisibles. Dans la bulle, mode Modifier = terminal complet (`git`, `gh`, `npm`…), consigne `shellPrompt`, et `--permission-mode bypassPermissions` au lieu de `dontAsk` : Claude Code protège tout chemin sous `.claude/` (donc les copies `.claude/worktrees/…`) et y refuse Edit/Write en dontAsk même autorisés ; c'est la bulle qui borne l'écriture. Les dossiers au-dessus du projet ne sont ouverts qu'en `file-read-metadata` (git et node font des `realpath`) ; sans bulle (décoché, profil refusé, serveur), seules les commandes de la liste avec « Commandes ». Une commande qui échoue sur « Operation not permitted » bute sur la bulle : élargir le profil dans `AgentSandbox.build`, jamais retirer la bulle. Il ne peut pas toucher à l'app installée. Accès au serveur depuis la bulle : `~/.ssh` est illisible, mais l'agent SSH de macOS (`SSH_AUTH_SOCK`) l'est ; `defaults read app.carnet.notes …` ne l'est plus (règle `user-preference-read` de `AgentSandbox.privacy`) : demander hôte, `user` et port à l'utilisateur ; tester avec `ssh -o BatchMode=yes -o UserKnownHostsFile=/tmp/kh -l <user> <hôte>` (pas de `timeout` sur macOS). Pour un diagnostic sur la machine, demande à l'utilisateur le résultat de `studio version` ; signale dans le compte rendu ce qui n'a pas pu être exécuté.
- **Updater, « plus récente »** : une Release n'est proposée que si son commit diffère de celui de l'app **et** qu'elle a été publiée après le build. Une app reconstruite aujourd'hui depuis de vieilles sources se croit donc à jour.
- **Fermeture de l'app** : elle répond « plus tard » à la demande de quitter (enregistrement en cours, 2 s au plus), puis installe un paquet déjà téléchargé (`applyOnQuit`). Tout script qui remplace l'app doit attendre la vraie fin du processus.
- **Pas de serveur, et l'app native ne reçoit pas de lien** : le schéma `carnet` n'est pas déclaré au système, donc un retour OAuth ne peut pas rouvrir l'app (Spotify passe par une adresse locale à recopier). Un domaine choisi par l'utilisateur (n8n auto-hébergé) reste bloqué par la CSP tant qu'il n'est pas dans `connect-src`.
- **Trousseau et signature ad hoc** : une signature `--sign -` change à chaque build et annule les « Toujours autoriser ». D’où le certificat autosigné « Studio Local » (`local_identity` dans `build-mac.sh`, créé une fois dans le trousseau de session, jamais en CI ni avec `STUDIO_ADHOC=1`) et `resignLocally` dans `Updater.swift`, qui re-signe avec lui une Release ad hoc quand l’app en cours l’utilise.
- **Demande Touch ID à l’ouverture du coffre** : `gate` (`hub.ts`) ne la lance que fenêtre au premier plan (`whenInFront`) ; le verrouillage automatique tombe souvent app en arrière-plan.
- **Éléments du trousseau d’autres outils** (jeton de Claude Code) : se lisent par `/usr/bin/security`, déjà autorisé, pas par `SecItemCopyMatching` (voir `keychainItem` dans `ClaudeUsage.swift`).
- **Cadres (iframe)** : il faut deux autorisations. `frame-src` dans `index.html`, et côté natif `framable` dans `Shell.swift` : sinon `decidePolicyFor` ouvre l’adresse du cadre dans le navigateur et le cadre reste vide. L’aperçu est rendu à nouveau à chaque frappe, ce qui recharge tout cadre placé dans une note : on l’ouvre donc dans une fenêtre (`modal`).
- **« Load failed »** : c’est l’échec réseau brut de WebKit (CORS, hors ligne, délai). `post` dans `ai.ts` le traduit (`NetworkError`) ; l’autotest de `native/macOS/main.swift` vérifie que `api.anthropic.com` reste joignable depuis la page.
- **Site en local, garde-fous** : la page n'envoie qu'un emplacement relatif, que `Sites.candidates` doit retrouver lui-même ; jamais de chemin ni de commande. Ajouter un emplacement ou un framework reconnu se fait dans `places` et `frameworks`. `project.local` doit rester hors de `REMOTE_ALLOWED` (un script `dev` exécute le code du projet).
- **Mobile, garde-fous et essais** : mêmes règles que le site (emplacement et appareil retrouvés par le Mac, jamais de chemin ni de commande ; `project.mobile` hors de `REMOTE_ALLOWED`). `adb shell` recolle ses arguments en une ligne sur l'appareil : tout texte venu de la page y passe par le filtre `link` et entre apostrophes. `Mobile.swift` s'essaie sans l'app : un `main` de quelques lignes avec des bouchons pour `Sites` (`find`, `searchPath`, `clean`, `descendants`), `ProjectFolders` et `Notifier`, compilé par `swiftc -parse-as-library` ; `xcrun simctl` fonctionne depuis la bulle d'un agent. Non essayés faute d'outils sur le Mac de développement : Android (adb, emulator), Flutter, et le build Xcode de bout en bout.
- **GitHub dit 404, pas 403, pour un dépôt que le jeton ne voit pas** (jeton à accès précis créé pour d'autres dépôts) : API et `git push` (« Repository not found »). Les refus passent par `refusal` (`GitHubError` avec `status` et `repo`, dans `github/api.ts`) et `gitError` (`Projects.swift`). Le push utilise les identifiants Git du Mac, la PR le jeton de Studio : l'un peut passer sans l'autre.
- **Vérifier depuis la bulle d'un agent** : Edit/Write peuvent y être refusés tant que l'app installée est antérieure au passage en bypassPermissions : écrire alors par le terminal (la bulle borne l'écriture à la copie). `node` est dans `/usr/local/bin` (hors du `PATH`, `export PATH=/usr/local/bin:$PATH`) ; `node scripts/…` y tourne. `npm run typecheck` (`tsc -p .` et `tsc -p src/sw`) depuis la copie ; côté Mac, `swiftc -parse-as-library -typecheck native/Shared/*.swift native/macOS/*.swift` vérifie les types de tout le pont (sans `-parse-as-library`, le `@main` de `main.swift` échoue). `check` reste à la CI : le dire dans le compte rendu.
- **Voir un rendu (agents compris)** : `node scripts/build.ts --test` puis `node scripts/shot.ts étape…` (`view=`, `click=<sélecteur ou texte>`, `js=`, `wait=`, `shot=<nom>`) écrit des PNG dans `/tmp/studio-shots`, à ouvrir avec Read. Sans dépendance : un navigateur Chromium du Mac (Brave, Chrome…) piloté sans fenêtre par le protocole DevTools, `--no-sandbox` dans la bulle. `window.__studio` (build de test) expose les modules : `news.open()`, `agentGuard.render([...])`, `app.setView`. Pas de pont natif dans ce build : `--pont scripts/shot-pont.js` simule l'app Mac (fonction `(msg) => réponse` injectée avant le chargement ; projet fictif, sessions, agent en cours avec trois sous-agents, tableau d'équipe ; les demandes non simulées sont listées en fin de course, à compléter là quand un écran appelle une nouvelle action). Piège déjà rencontré grâce à une capture : un préfixe CSS de deux lettres peut déjà exister (`.ac` = menu d'autocomplétion dans `app.css`, d'où le conteneur d'Activité `.ac-wrap`) : chercher la classe nue avant de la choisir. Regarder ses captures avant de rendre un travail d'interface. **GitHub simulé** : `js=` avec `__studio.vault.create('…')` puis `vault.setSecret('github','x')`, et `window.fetch` remplacé pour `https://api.github.com` (sinon « Le coffre est fermé »).
- **Vie privée des agents** : dans la bulle, `AgentSandbox.privacy` ferme Apple Events, caméra, micro, localisation, presse-papiers (`com.apple.pasteboard.1`) et les préférences/caches des apps d'activité ; `cfprefsd` (`defaults read`) ignore les règles de fichiers, d'où les règles `user-preference-read`. Chaque règle est validée seule par `sandbox-exec` (une bulle imbriquée ne se teste pas depuis la bulle d'un agent : `sandbox_apply: Operation not permitted`). Hors serveur, `AgentPermissions.privateReads` passe `--disallowedTools Read(//…/**)` (dossiers personnels, autres projets, sauf un dossier qui contient le projet). `AgentTuning.env` coupe télémétrie et rapports d'erreur de Claude Code.
- **Garde des agents** (`native/Shared/AgentGuard.swift`, `src/features/projects/guard.ts`, `css/guard.css`) : tout agent local qui a Bash reçoit par `--settings` un hook PreToolUse (curl vers un serveur de l'app sur 127.0.0.1) ; suppression ou installation (tri par expressions, `AgentGuard.risk`) attend « Autoriser » + Touch ID ou mot de passe (`agent guard`, `agent guardAnswer`, signal `window.carnet.agentGuard`), refus au bout de 9 min ou si l'app ne répond pas (code 2). Exception voulue par l'utilisateur : une suppression dont chaque chemin, écrit en clair, tombe dans le dossier de travail (mode Modifier : copie + copies des autres dépôts, `roots` de `settings`) passe sans question (`AgentGuard.local` : découpe shell maison, `cd` suivis, liens résolus, `.git` et racine exclus ; variable, `~`, `sudo`, `xargs`, `-exec`, `<<` → on redemande) ; les installations demandent toujours. Le tri ignore les données (`strip`/`scanned` : corps des `<<` et contenu des guillemets, sauf `$(`) tant qu'aucun interpréteur (`runsText` : sh, python, ssh…) n'est dans la ligne ; sinon un message écrit au tableau par `cat <<'EOF'` qui citait « npm install » ou « rm » demandait Touch ID. Tri sur le texte de la commande seulement : la borne dure reste la bulle, où l'écriture est fermée partout sauf copie, `.git`, caches, `/tmp`, `/var/folders` et `/dev`. Une bulle ne s'imbrique pas (`sandbox-exec` y échoue) : un profil modifié ne se teste que depuis l'app.
- **Tableau d'équipe** (`AgentBoard`, `Agents.swift`) : dossier `<dépôt>/.git/studio-equipe/<copie, ou groupe pour ses agents et sa mère>/`, un fichier Markdown par auteur (`principal.md`, `agent-N.md`, `<sous-agent>.md`, `utilisateur.md`) pour éviter les écritures concurrentes. Créé par `Agents.start` en mode Modifier sur ce Mac si l'agent a des sous-agents ou fait partie d'un groupe ; la consigne d'orchestration (plan, fichiers réservés, contrats, vagues) est dans `AgentBoard.prompt`. Hors bulle il passe par `--add-dir`. Pont `agent board` (lecture, ou `note` → `utilisateur.md`), affiché dans l'Espace agents (`toggleBoard`, T). Une entrée s'écrit `- [HH:MM] → destinataire : texte` (`tous`, `principal`, un nom, `utilisateur`) : `AgentBoard.read` découpe les fichiers en `messages` (`at`, `from`, `to`, `text`) pour le fil « Échanges ».
- **Sous-agents et `claude -p`** : un sous-agent lancé en tâche de fond garde le processus ouvert après le compte rendu (plusieurs événements `result`, agent encore « occupé ») ; `AgentTeam.env` pose donc `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` (l'agent attend ses sous-agents, lancés en parallèle dans un même message) et `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`. Dans le flux, un message de sous-agent porte `parent_tool_use_id` : `ingest` n'en garde que les outils. La doc qui fait foi : `code.claude.com/docs/en/sub-agents.md` et `cli-reference.md`.
- **`npm run verify` cherche des secrets** (`SECRET` dans `scripts/check.ts`) : un en-tête `BEGIN … PRIVATE KEY` écrit d'un bloc dans le code le fait échouer (d'où l'en-tête en deux morceaux dans `SSHKeys.generate`).
- **Réponse du Mac non JSON = app plantée** : `JSONSerialization.data(withJSONObject:)` lève une exception Objective-C (que `try?` n'attrape pas) sur un `ArraySlice` (`.suffix`/`.prefix` non convertis par `Array(…)`), une `Date`, un tuple… `answer`/`reply` (`Shell.swift`) vérifient `isValidJSONObject` d'abord ; garder des types JSON purs.
- **Journaux de Claude Code** : `~/.claude/projects/<chemin encodé>`, chaque unité UTF-16 hors `[a-zA-Z0-9]` devient « - » (accents compris) ; `ClaudeSessions.dirs` doit suivre exactement cette règle, sinon aucune session du projet n'est retrouvée.
- **Dépendances** : `lib/` et `core/` n'importent jamais `features/` ni `integrations/`.
- **Pont natif, origine** : `ShellCoordinator.trusted` (`Shell.swift`) ignore tout message qui ne vient pas du cadre principal de `carnet://app` (le pont est installé dans tous les cadres, Figma compris) ; `data:` n'est jamais permis dans la fenêtre principale (pas de CSP), et un cadre ne charge jamais `carnet://`. Un `agent start` venu d'un appareil lié porte `remote: true` (posé par `onRpc` de `link.ts`) : `Agents.start` (`fromLink`, `Queued.remote` pour les messages en attente) lui retire Bash, bulle ou pas.
- **Index des notes** (`store.index()`) : `setBody` ne le jette que si les tags ou les liens de la note changent ; un changement de titre n'y entre qu'à l'enregistrement (`emit`). Piège : tout appel avant `store.init()` (ex. `i18n.guard` dans `start()` de `src/app.ts`) le calcule vide ; `load()` le jette, sinon le carnet paraissait vide au redémarrage jusqu'à la première écriture.
- **Rendus périodiques** : `paintIfChanged(el, html)` (`src/ui/kit.ts`) plutôt que `innerHTML =` ; toute relecture périodique s'arrête quand `document.hidden`. Éditeur : aperçu différé en mode Écrire (`schedulePreview(délai)`), sous-notes et rétroliens refaits seulement quand l'index change (`linksCache`, `app.ts`).
- **Appairage** (`link.ts`) : une invitation non acceptée expire après `INVITE_TTL` (15 min) et un appareil lié est figé sur son `id` ; un appareil qui a perdu son identité (stockage effacé) doit être lié à nouveau.
- **Textes d'interface** : apostrophe typographique `’` dans les chaînes TypeScript, et `esc()` sur toute donnée insérée dans du HTML.
- **CSS par fonctionnalité** : `css/app.css` est groupé par esbuild ; un nouveau fichier (`css/commerce/*.css`) s'ajoute par `@import` en tête d'app.css (`news.css`, `pulse.css`, `activity.css`, `team.css`, `noteseal.css`). Goût constant de l'utilisateur : sobre, neutre, outil de travail ; ni cartes à icône teintée, ni dégradé, ni halo, ni animation démonstrative. Nuance du 23 nov. 2026 (demande explicite) : « du motion design, beaucoup, pour les interactions » et un fond d'environnement : le mouvement est bienvenu quand il accompagne un geste (transition, glissement, retour d'action), pas en décor gratuit ; les refus ci-dessus tiennent toujours.
- **Commerce** : Marketplace n'a pas d'API de publication (emplacement de pub seulement, jamais seul) ; une campagne Meta se crée toujours en `PAUSED` et l'IA n'a aucun outil pour activer ou créer une pub. Rien de cela n'a encore tourné sur une vraie boutique : les requêtes GraphQL (2026-04) et Marketing API (v25.0) sont à vérifier au premier essai.
- **Typage et build dans la bulle des agents** : node est installé (`/usr/local/bin/node`) ; l'app lancée du Dock n'a que `/usr/bin:/bin:/usr/sbin:/sbin`, d'où un agent local qui part avec `Sites.searchPath()` (Homebrew, /usr/local/bin, ~/.local/bin, volta, bun, pnpm ; dans `Agents.swift`, au lancement) et une consigne `shellPrompt` « chercher avant de dire qu'un outil manque ». Avec une app plus ancienne : `export PATH=/usr/local/bin:$PATH`. Ne jamais conclure « pas de node » sans ce chemin. Copie sans lien `node_modules` (app antérieure à `linkDependencies`) : `npm ci` dans la copie (4 paquets, 1 s, confirmation de l'utilisateur) ; Swift : `swiftc -parse-as-library -typecheck native/Shared/*.swift native/macOS/*.swift`.
