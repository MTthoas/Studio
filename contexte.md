# Contexte du dépôt

Mémoire du dépôt pour les agents : à lire **en premier**, avant toute recherche, pour ne pas réexplorer le code à chaque demande. Studio l'impose à chaque agent Claude Code (consignes « Mémoire du dépôt », Réglages → Consignes et contexte).

**L'entretenir** — à la fin d'un travail, ajoute ici ce que tu as appris de durable et qui t'aurait fait gagner du temps : une ou deux lignes, dans la bonne section. Corrige ou retire ce qui est devenu faux. Pas de journal, pas d'état d'avancement, rien que le code dise déjà en clair. Désigne le code par fichier et nom de fonction, jamais par numéro de ligne. Si le code contredit ce fichier, c'est le code qui a raison : corrige le fichier.

## En bref

- Studio : notes, tâches, projets, agents Claude Code. Une app web en TypeScript strict (`src/` → `dist/` par esbuild, sans framework), embarquée telle quelle dans une coquille Swift pour Mac et iPhone (`native/`).
- La carte complète des fichiers est dans `README.md`, section « Architecture » : ne la recopie pas ici, lis-la au besoin.
- Tout est rédigé en français : interface (tutoiement), commentaires, README, messages des scripts. Les commits sont en anglais, au format Conventional Commits.

## Où trouver quoi

- **Barre latérale et menu « Studio ▾ »** (dans la fenêtre) : `src/app.ts`, `workspaceMenu` et le rendu de la barre juste au-dessus. À ne pas confondre avec le menu **Studio** de la barre de menus macOS : `buildMenu` dans `native/macOS/main.swift`.
- **Clics** : une seule écoute déléguée, `onClick` dans `src/app.ts`, qui lit `data-act`, `data-open-conn`…
- **Réglages** : `src/features/hub.ts`. `TABS` liste les onglets, `TAB_BODY` leur contenu, `hub.openConnections('<onglet>')` en ouvre un. Onglets : `coffre`, `ia`, `consignes`, `linear`, `github`, `extensions`, `appareils`, `apparence`, `donnees`, `maj`.
- **Plugins** : `src/plugins/registry.ts` (types `Plugin`, `PluginAPI`, activation, cycle de vie, clics `data-plug="<id>:<action>"`), enregistrés dans `builtin.ts`. Optionnels : `spotify.ts`, `n8n.ts`, `figma.ts`. Un plugin peut rendre des blocs ```<langage> (`fences`, appelés par `hub.fenceFor` après les blocs maison). Leur page de réglages (onglet `extensions`) est générée par `src/features/plugins.ts` ; le bloc de barre latérale est `#plug-side`, redessiné seul par `registry.refresh()` ; chaque plugin y enveloppe son widget dans une `.plug-card` (styles dans `css/app.css`, près de `.side-foot`). Événements délégués depuis `src/app.ts` : clic `data-plug`, formulaire `data-plug-form`, `change` `data-plug-change` (curseurs).
- **Spotify, autorisations** : le jeton garde ses `scope` ; ajouter un scope à `SCOPE` n'affecte pas les connexions existantes, d'où les tests du type `canVolume` et l'invitation à se reconnecter.
- **Mises à jour de l'app Mac** : `src/core/update.ts` (état, automatismes) parle à `native/Shared/Updater.swift` (Releases GitHub, téléchargement, remplacement). L'onglet est `tabUpdate` dans `hub.ts` ; la fenêtre « version prête » et les nouveautés sont dans `src/features/news.ts`.
- **Pont web ↔ natif** : `native.call(type, action, …)` dans `src/core/native.ts` ; côté Swift, `userContentController` de `native/Shared/Shell.swift` aiguille selon `type`, et répond par `window.carnet.reply`. La page sait où elle tourne par `document.documentElement.dataset.native` (`mac`, `ios`, absent dans un navigateur).
- **Consignes envoyées à l'IA** : `src/integrations/tuning.ts` pour les automatisations, les tâches de fond et les limites de contexte. Celles des agents Claude Code vivent sur le Mac : `AgentTuning`, en bas de `native/Shared/Agents.swift`.
- **Autorisations des agents** (outils par mode, commandes de la case « Commandes », web, PATH) : `AgentPermissions`, en bas de `native/Shared/Agents.swift`, gardé dans UserDefaults ; action de pont `agent.permissions` (`Shell.swift`), page `src/features/permissions.ts` (onglet `autorisations`). Le formulaire de consigne lit `permissions.commandsInRead()` pour activer la case en mode Analyser. Navigateur : `browserSetup` (Playwright MCP par `npx`, `--allowed-origins` = `sites`) passé en `--mcp-config` (seul serveur, à cause de `--strict-mcp-config`) et permis par la règle `mcp__browser` ; jamais sur serveur ni pour l'orchestrateur (`internal`). Le même serveur (`browserCommand`) sert l'IA de Studio, tous fournisseurs : `native/Shared/Browser.swift` (client MCP stdio, pont `type: "browser"`, `tools`/`call`/`stop`), outils ajoutés par `browserTools` dans `ai.ts` quand la liste d'outils contient `navigateur` (aucune donnée de projet : hors filtre de périmètre).
- **Notes et tâches créées par les agents** : l'agent écrit des blocs ```studio-tâches / ```studio-note Titre en fin de compte rendu (format dicté par `AgentPermissions.itemsLine`). `AgentItems.extract` (bas de `Agents.swift`) les retire du résultat, `AgentItems.add` les garde dans UserDefaults et prévient la page (`window.carnet.agentItems`) ; `src/features/projects/items.ts` les crée puis confirme (`agent.itemsDone`). Seul le Mac les crée : `agent.items` et `agent.itemsDone` restent hors de `REMOTE_ALLOWED`.
- **Agents Claude Code** : lancement et arguments de `claude` dans `native/Shared/Agents.swift` ; copies isolées dans `.claude/worktrees/studio-…` (`Projects.swift`) ; publication en pull request dans `Orchestrator.swift` ; l'interface dans `src/features/projects/sessions.ts`. Claude Code retrouve une session par son dossier (`ClaudeSessions.cwd`) : reprendre une discussion dont la copie a été supprimée passe par `restoreWorktree` (`Projects.swift`, appelé dans `Agents.start`), qui la recrée au même chemin. Une copie se rattache à sa conversation par `Session.worktree` (nom du dossier) ; « Copies à relire » (`treeRow`) l'affiche sous le nom de cette conversation (`treeTitle` → `nameOf`), la branche `worktree-studio-…` n'est qu'en infobulle. La liste des conversations vient de `ClaudeSessions.list` (`native/Shared/Sessions.swift`, 25 journaux relus) et se range par `active` (dernier échange), pas par date de fichier ; côté page, `known` est gardé dans localStorage (`studio.cc.sessions`, `at: 0` = à relire) pour un affichage immédiat. L'étape d'une copie (au travail, à publier, PR, fusionné) se calcule à un seul endroit, `stageOf` / `STAGES` ; liste, cartes, fil et barre latérale (`sideSessions().stage`) en dépendent. `trees` ne vaut que pour le projet `treesFor`.
- **État des copies, Mac + GitHub** (`sessions.ts`) : `rawTrees` (réponse de `agent worktrees`) complété par `withPulls` d'après `github.branchPulls` (dernière PR de chaque branche, lue à `mount` puis toutes les 30 s) donne `trees` ; une PR fusionnée compte si son `sha` égale `Worktree.head`. Rien de lent n'est attendu par l'affichage : copies relues par `treesInBackground` puis `repaintList`, dernier état gardé dans localStorage (`studio.cc.trees`, `restoreTrees`). Côté Mac, `worktrees` lance le `git fetch` en arrière-plan (`fetching: true` → la page redemande au tour suivant) ; `fresh: true` le fait d'abord, envoyé une fois quand GitHub voit une fusion que le Mac ignore.
- **Périmètres de l'IA** (cloisonnement par projet) : `src/integrations/scope.ts`. Toute exécution reçoit `ctx.scope` (projet ou `GENERAL` par défaut) et `toolset` dans `ai.ts` filtre chaque outil avec `noteIn`/`taskIn`/`repoIn`/`needLinear`. Linear n'existe qu'avec un projet dont le champ `linear:` désigne un projet Linear au nom exact (`projectByName`). Les automatisations prennent le leur avec `projet:` ; les événements portent une `origin` (`core/events.ts`) et `hub.onEvent` ne les livre qu'au bon périmètre. Tout nouvel outil ou toute nouvelle source de données pour l'IA doit passer par ce filtre.
- **Page Claude** (toujours dans un projet, fixé à la création, `Chat.project` ; volontairement absente de la barre latérale et de la palette, on y entre par `chat.startIn` depuis la fiche projet) : `src/features/chat.ts`, vue `claude` ; conversations dans le magasin IndexedDB `chats` (`db.ts`) ; consigne `auto.chat` et limite `ctx.chat` dans `src/integrations/tuning.ts` ; `ai.run({ chat: true })`.
- **Boutique / e-commerce** (lecture seule, app Mac et iPhone) : socle dans `src/integrations/commerce/`. `core.ts` = types neutres (`Order`, `Snapshot`, `Provider`) et calculs purs (`stats`, `counted`, `toShip`, `money`), sans import : testable avec `node` seul. `shopify.ts` = seul fournisseur, API Admin GraphQL, traduit vers ces types ; un autre fournisseur = un autre `Provider` dans `PROVIDERS` (`index.ts`). `index.ts` relie une boutique à UN projet (champ `boutique:` du bloc projet → `Project.shop` ; identifiants dans le secret de coffre `commerce`, par adresse), garde les chiffres 2 min (`snapshot`), et surveille les nouvelles commandes toutes les 3 min (`poll` : notification + événement `commande`, origine `shop`). Shopify refuse les appels d'une page (pas de CORS) : tout passe par le pont `type: "commerce"` (`graphql`, `token`) → `native/Shared/Commerce.swift`, qui ne joint que `*.myshopify.com` (hors `REMOTE_ALLOWED`). La version d'API est `Commerce.version`. Vue : `src/features/projects/shop.ts` (onglet `shop`, clics `data-shp`, carte de la vue d'ensemble). IA : `shopTools` dans `ai.ts` (famille `boutique`), filtrés par `scope.hasShop`/`needShop`. Aucune donnée de client n'est demandée : à garder ainsi (l'IA reçoit ces données). Non essayé sur une vraie boutique à l'écriture : seulement contre une API simulée et les réponses d'erreur réelles de Shopify.
- **Docker** (lecture seule, app Mac) : `Docker.status` dans `native/Shared/Docker.swift` lit la socket du moteur (trois GET fixes) et rattache conteneurs et images aux projets par leur dossier (étiquettes Compose et devcontainer, dossiers montés, copies `.claude/worktrees/`) ; action de pont `docker.status` (`Shell.swift`, hors `REMOTE_ALLOWED`) ; vues dans `src/features/projects/docker.ts` (onglet `docker` de `page.ts`, carte de la vue d'ensemble, bloc de `home.ts`).
- **Plusieurs dépôts côté Mac** (`Projects.swift`, « Plusieurs dépôts par projet ») : `path(pid)` est le dossier du dépôt principal (celui des sessions Claude Code et des copies « principales ») : choisi par `pick`, sinon retrouvé (premier de `repos`) dans le **dossier mère** `home(pid)` (action `project home`, `pickHome`, UserDefaults `studio.projectHomes` ; un dossier Git choisi comme dossier mère devient le dépôt principal). `shelf(pid)` = dossier mère, sinon parent du principal : on y cherche (`findClone`) et on y clone. Recadrages : `.solo` (vue seule, 920 px), `.no-side` (liste + note, 1040 px), `.short`/`.tall` (hauteur), `.frag` (un morceau sans cadre, pour les cases du bento `.cell .piece`). Une automatisation affiche son `planning` tel qu'écrit (`jours ouvrés 8h30`), comme `agents()` dans `home.ts`. Il n'y a aucune vraie capture dans le dépôt.

## Recettes

- **Ajouter une consigne d'agent** : dans `AgentTuning`, une clé dans `textKeys`, sa valeur dans `defaults`, sa place dans `prompt()` ; puis le champ dans `AGENT_ITEMS` et `AGENT_PROMPT` de `src/features/tuning.ts`.
- **Ajouter une autorisation d’agent** : une propriété et sa clé (`flags` pour un booléen, avec sa valeur d’origine) dans `AgentPermissions`, son effet dans `tools()` ou `allowed()`, sa valeur d’origine dans `state()` ; puis le champ dans `bodyHTML()` de `src/features/permissions.ts`. Garder les valeurs d’origine identiques aux garde-fous existants.
- **Ajouter une consigne ou une limite côté web** : une entrée dans `DEFS` de `src/integrations/tuning.ts` suffit, la page de réglages se construit dessus.
- **Ajouter un plugin optionnel** : un fichier `src/plugins/<id>.ts` exportant un `Plugin` (`optional: true`, `settings`, `hosts`, `start`, `sidebar`, `commands`, `actions`), un `registry.register` dans `builtin.ts`, et ses domaines dans `connect-src` de `index.html` (sinon la CSP bloque ses requêtes) ; le README les liste.
- **Annoncer une fonction visible** : une entrée en tête de `NEWS` dans `src/features/news.ts` (identifiant stable), et le README. Pas de paragraphe : un titre qui nomme la fonction (30 caractères au plus, sans slogan ni « ton/tes »), une phrase factuelle (`lead`), deux à quatre `bits` (icône, mot-clé, précision : rendus en table à deux colonnes), le chemin `where`, et un schéma `visual` (`flow` fléché, `chips`, `stack`). La fenêtre (`viewer`, styles `.wn-*`) a un sommaire par date et une fiche, neutres comme les Réglages : `hue` ne teinte que les icônes. Refusés par l'utilisateur : les nouveautés « en texte, sans mots-clés ni infos visuelles », puis le carrousel à illustration teintée (dégradé, halos flous, pastilles colorées, titres-slogans), jugé « trop IA ».
- **Conflit sur `NEWS`** (chaque PR ajoute son entrée en tête, donc les fusions avec `main` s'y heurtent souvent) : garder les entrées des deux côtés, la plus récente en tête, sans en perdre ni en dupliquer. Vérifier ensuite que chaque `id` présent sur `origin/main` l'est encore.
- **Vérifier** : `npm run verify` (types, build, cache hors ligne, aucun secret). C'est ce que lance la CI.

## Build et versions

- L'app Mac embarque ses fichiers web : un changement dans `src/` n'y apparaît qu'après reconstruction (`studio update`) ou installation d'une Release.
- `native/build-mac.sh` inscrit `StudioCommit` et `StudioBuilt` dans l'`Info.plist` ; l'updater et `studio version` s'en servent.
- La CI (`.github/workflows/build.yml`) publie une Release à chaque push sur `main`, avec `Studio-macOS.zip`. Les pull requests sont fusionnées sur GitHub : le dossier local ne les reçoit pas tout seul.
- **Signature de l'app Mac** : ad hoc par défaut ; `SIGN_IDENTITY` (posé par la CI sur un push, si les secrets `MACOS_CERTIFICATE`… existent) fait signer `build-mac.sh` en Developer ID avec hardened runtime et `native/macOS/Studio.entitlements`, puis le job `macos` notarise et agrafe. Sous hardened runtime, toute nouvelle ressource protégée (caméra, Apple Events…) demande son droit dans ce fichier, sinon elle échoue en silence dans l'app publiée seulement.
- **Installeur** : `site/install.sh`, servi par Pages (`curl … | sh`), prend le zip de la dernière Release sans quarantaine. Tant que l'app n'est pas notarisée, c'est la voie d'installation mise en avant (README, site) ; un zip téléchargé au navigateur est bloqué par Gatekeeper.
- `studio update` avance donc d'abord `main` jusqu'à GitHub (avance simple), puis construit ; `studio update --local` construit tel quel ; `studio version` compare app installée, dossier et GitHub.

## Pièges

- **Anciens noms gardés exprès** : identifiant de bundle `app.carnet.notes`, schéma `carnet://`, pont `window.carnet`, base IndexedDB `carnet`. Les renommer ferait perdre les données des apps installées.
- **Un agent lancé par Studio est confiné** : `--restricted`, et sur le Mac une bulle Seatbelt (`native/Shared/AgentSandbox.swift`, `sandbox-exec -p`, réglage `terminal` coché à l'origine) : écriture limitée à sa copie, au `.git` du dépôt et aux caches ; données de Studio, autres projets et autres sessions illisibles. Dans la bulle, mode Modifier = terminal complet (`git`, `gh`, `npm`…), consigne `shellPrompt` ; sans bulle (décoché, profil refusé, serveur), seules les commandes de la liste avec « Commandes ». Une commande qui échoue sur « Operation not permitted » bute sur la bulle : élargir le profil dans `AgentSandbox.build`, jamais retirer la bulle. Il ne peut pas toucher à l'app installée. Pour un diagnostic sur la machine, demande à l'utilisateur le résultat de `studio version` ; signale dans le compte rendu ce qui n'a pas pu être exécuté.
- **Updater, « plus récente »** : une Release n'est proposée que si son commit diffère de celui de l'app **et** qu'elle a été publiée après le build. Une app reconstruite aujourd'hui depuis de vieilles sources se croit donc à jour.
- **Fermeture de l'app** : elle répond « plus tard » à la demande de quitter (enregistrement en cours, 2 s au plus), puis installe un paquet déjà téléchargé (`applyOnQuit`). Tout script qui remplace l'app doit attendre la vraie fin du processus.
- **Pas de serveur, et l'app native ne reçoit pas de lien** : le schéma `carnet` n'est pas déclaré au système, donc un retour OAuth ne peut pas rouvrir l'app (Spotify passe par une adresse locale à recopier). Un domaine choisi par l'utilisateur (n8n auto-hébergé) reste bloqué par la CSP tant qu'il n'est pas dans `connect-src`.
- **Trousseau et signature ad hoc** : une signature `--sign -` change à chaque build et annule les « Toujours autoriser ». D’où le certificat autosigné « Studio Local » (`local_identity` dans `build-mac.sh`, créé une fois dans le trousseau de session, jamais en CI ni avec `STUDIO_ADHOC=1`) et `resignLocally` dans `Updater.swift`, qui re-signe avec lui une Release ad hoc quand l’app en cours l’utilise.
- **Demande Touch ID à l’ouverture du coffre** : `gate` (`hub.ts`) ne la lance que fenêtre au premier plan (`whenInFront`) ; le verrouillage automatique tombe souvent app en arrière-plan.
- **Éléments du trousseau d’autres outils** (jeton de Claude Code) : se lisent par `/usr/bin/security`, déjà autorisé, pas par `SecItemCopyMatching` (voir `keychainItem` dans `ClaudeUsage.swift`).
- **Cadres (iframe)** : il faut deux autorisations. `frame-src` dans `index.html`, et côté natif `framable` dans `Shell.swift` : sinon `decidePolicyFor` ouvre l’adresse du cadre dans le navigateur et le cadre reste vide. L’aperçu est rendu à nouveau à chaque frappe, ce qui recharge tout cadre placé dans une note : on l’ouvre donc dans une fenêtre (`modal`).
- **« Load failed »** : c’est l’échec réseau brut de WebKit (CORS, hors ligne, délai). `post` dans `ai.ts` le traduit (`NetworkError`) ; l’autotest de `native/macOS/main.swift` vérifie que `api.anthropic.com` reste joignable depuis la page.
- **Site en local, garde-fous** : la page n'envoie qu'un emplacement relatif, que `Sites.candidates` doit retrouver lui-même ; jamais de chemin ni de commande. Ajouter un emplacement ou un framework reconnu se fait dans `places` et `frameworks`. `project.local` doit rester hors de `REMOTE_ALLOWED` (un script `dev` exécute le code du projet).
- **GitHub dit 404, pas 403, pour un dépôt que le jeton ne voit pas** (jeton à accès précis créé pour d'autres dépôts) : API et `git push` (« Repository not found »). Les refus passent par `refusal` (`GitHubError` avec `status` et `repo`, dans `github/api.ts`) et `gitError` (`Projects.swift`). Le push utilise les identifiants Git du Mac, la PR le jeton de Studio : l'un peut passer sans l'autre.
- **`npm run verify` cherche des secrets** (`SECRET` dans `scripts/check.ts`) : un en-tête `BEGIN … PRIVATE KEY` écrit d'un bloc dans le code le fait échouer (d'où l'en-tête en deux morceaux dans `SSHKeys.generate`).
- **Réponse du Mac non JSON = app plantée** : `JSONSerialization.data(withJSONObject:)` lève une exception Objective-C (que `try?` n'attrape pas) sur un `ArraySlice` (`.suffix`/`.prefix` non convertis par `Array(…)`), une `Date`, un tuple… `answer`/`reply` (`Shell.swift`) vérifient `isValidJSONObject` d'abord ; garder des types JSON purs.
- **Journaux de Claude Code** : `~/.claude/projects/<chemin encodé>`, chaque unité UTF-16 hors `[a-zA-Z0-9]` devient « - » (accents compris) ; `ClaudeSessions.dirs` doit suivre exactement cette règle, sinon aucune session du projet n'est retrouvée.
- **Dépendances** : `lib/` et `core/` n'importent jamais `features/` ni `integrations/`.
- **Textes d'interface** : apostrophe typographique `’` dans les chaînes TypeScript, et `esc()` sur toute donnée insérée dans du HTML.
